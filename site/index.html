O problema

A maioria das conversas sobre criar um sistema pula para como construir antes de o que exatamente estamos construindo estar claro. A documentação sai com cara de completa e esconde decisões que ninguém tomou. Elas aparecem depois, no meio do código, quando o agente escolhe sozinho.

Como funciona

Três etapas. Você decide quando avançar.

A skill nunca pula de etapa sozinha. Cada uma tem uma responsabilidade e uma saída próprias.

ETAPA 1

Concept

Conversa investigativa. Cada pergunta traz um palpite para você confirmar ou corrigir, e a skill propõe o que você talvez não tenha pensado. Casos de borda e o que sistemas do mesmo domínio tiveram de resolver voltam como pergunta, nunca como funcionalidade adicionada por conta própria.

Você diz"Tenho uma clínica e perco a manhã confirmando consulta por WhatsApp."

ETAPA 2

Blueprint

Antes de escrever qualquer coisa, um checkpoint obrigatório separa o que foi decidido do que ficou em aberto. Depois, o PROJECT.md: 22 seções, cada decisão com um ID.

Você diz"Temos o suficiente, vamos consolidar."

ETAPA 3

Files-Gen

Cada documento é uma projeção do Blueprint. Cita IDs, não inventa; marca como PENDENTE o que não foi decidido; registra de qual versão saiu.

Você diz"Gera o PRD, depois o modelo de dados."

Checkpoint

Nada vira requisito sem você dizer sim.

Antes de toda consolidação, a skill mostra o que entendeu em quatro categorias. Proposta não respondida não vira decisão, e contradição não é resolvida por palpite.

Definido

O que você afirmou ou aceitou.

  • Remarcação grátis até 24h antes BR-01
  • Confirmação automática por WhatsApp FUN-02

Pendente

Sem resposta, separado por gravidade.

  • Quem libera o bloqueio por falta? crítica
  • Texto padrão do lembrete menor

Sugestão futura

Proposto, nem aceito nem recusado.

  • Lista de espera para horários liberados
  • Lembrete também por e-mail

Inconsistência

Contradição para você resolver.

  • "24h antes" na rodada 2, "48h antes" na rodada 5. Qual vale?

Rastreabilidade

Verificado por script, não por memória.

IDs só nascem no Blueprint. Seis scripts em Python conferem o que a conversa não consegue garantir.

  • ID inventadocheck_traceability.py aponta, com arquivo e linha, todo ID citado que não existe no Blueprint.
  • Mudou uma regra?find_references.py lista todo documento que a cita, e a skill mostra o plano de propagação antes de editar.
  • Documento atrasadocheck_staleness.py compara a versão do Blueprint com a de cada derivado. check_coverage.py acha a regra que nunca chegou ao documento onde é obrigatória.
  • Pronto para implementar?handoff_check.py bloqueia a entrega com pendência crítica aberta ou import quebrado no CLAUDE.md.

Entrega ao Claude Code

Um contrato, não um resumo.

O CLAUDE.md fica abaixo de 200 linhas, e cada linha muda o que o agente faz: comandos, regras invioláveis, Definition of Done, o que não implementar nesta fase e o que fazer quando dois documentos discordam. O resto vem por import, sob demanda.

O STATE.md nasce junto e liga uma sessão de implementação à seguinte sem depender da conversa anterior.

CLAUDE.mdtrecho
## Quando os documentos discordam
1. Decisão do usuário nesta sessão
2. @PROJECT.md (fonte primária)
3. Demais documentos
4. Código e testes existentes

Conflito em regra de negócio, permissão ou
dado pessoal: pare e pergunte. Não escolha.

## Nunca faça
- Enfraquecer um teste para ele passar.
- Adicionar dependência sem aprovação.
- Validar só no cliente.

## Início e fim de sessão
Leia @STATE.md ao começar. Sobrescreva ao terminar.

Instalar

Pronta em dois minutos.

Sem comando para lembrar: depois de instalada, a skill dispara quando você apresenta um problema e uma ideia de sistema.

  1. Baixe o vibe-docs.skill do último release.
  2. Em Customize → Skills, clique em + → Upload a skill e envie o arquivo. Deixe a execução de código ligada para a skill gravar arquivos e rodar os scripts.
  3. Abra uma conversa e apresente o problema. Ela começa pelas perguntas, sem gerar documento ainda.
  1. Clone o repositório e copie a pasta da skill para as suas skills pessoais: 
    git clone https://github.com/padilhars/vibe-docs.git
mkdir -p ~/.claude/skills
cp -r vibe-docs/vibe-docs ~/.claude/skills/
  2. Para valer só num repositório, use <repo>/.claude/skills/vibe-docs/.
  3. Peça "me ajuda a pensar num sistema para…" e acompanhe o PROJECT.md nascer na pasta do projeto.
